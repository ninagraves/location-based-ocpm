# Running example

The running example of `overview/Deriving Locations.md` (section "Setting") as an uploadable OCEL 2.0 log.
Generated by `make_running_example.py` (the single source; never edit the outputs by hand).

- `running_example.sqlite`: 17 events, 6 handling units (slab s1, coils c1 to c5), 28 e2o relations.
- `inputs/*.csv`: the configuration inputs as tables (handling units, movement events, transformation events, target and pickup locations), `inputs/locations.csv`, the location context for visits (agg, vehicles, storage units; draft), `inputs/processing_events.csv` (processing operations P: cast slab, roll, label, cut; draft) and `inputs/transformation_roles.csv` (consumed/produced handling units at the transformation events, columns `event`, `hu`, `role`; the same as the e2o qualifiers).
- `derived/locations_level_{k}.csv`: the derived location mapping of each level k = 0..3, written by `notebooks/location_derivation.ipynb` (see `docs/resources/location-derivation.md`, section 7).
- `derived/transformation_roles.csv`: the consumed and produced handling units resolved from the running example configuration (default option 5, first and last timestamps), written by `notebooks/transformations.ipynb` (see `docs/resources/transformation-inputs.md`).
- `derived/maximal_visits_level_3_kappa_2.csv`: the maximal visits at Level 3 with κ = 2, written by `notebooks/visits.ipynb` (see `docs/resources/visits.md`).
- `configuration.json`: the configuration below, for "Load configuration" in the form, including the location context (hand-written; tests check it matches the tests' configuration and derives the high-level locations). Its location table is called `locations.csv`, so upload `inputs/locations.csv` in one of the location-context table fields after loading it.

## Configuration that reproduces the example
- Handling units: object types `slab`, `coil` (or `inputs/handling_units.csv`, column `object`).
- Movement events: activities `crane move`, `load truck`, `unload truck` (or attribute `event_group` = `transport`, or `inputs/movement_events.csv`).
- Transformation events: activities `cast slab`, `roll`, `cut` (or attribute `event_group` = `transformation`, or `inputs/transformation_events.csv`).
- Target locations: event attribute `to_loc` (or `inputs/target_locations.csv`, columns `event`, `location`).
- Pickup locations: event attribute `from_loc` (or `inputs/pickup_locations.csv`).
- Location context (optional, included in `configuration.json`), all from the table `inputs/locations.csv`:
  - high-level locations: columns `location` and `high_level` (A1, A2 → A; B1 → B; T not mapped, so it stays T);
  - vehicles: column `location`, true/false column `is_vehicle` (T);
  - storage units: column `location`, true/false column `is_storage` (B1);
  - processing operations: activity `label`, plus all transformation events (cast slab, roll, cut).

Example time t is 2026-01-01 00:00 plus t hours.
E2O qualifiers: `produced`/`consumed` at the transformation events, `handled` otherwise (used by the object timeline via `inputs/transformation_roles.csv`).

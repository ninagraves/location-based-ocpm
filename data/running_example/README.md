# Running example

The running example of `overview/Deriving Locations.md` (section "Setting") as an uploadable OCEL 2.0 log.
Generated by `make_running_example.py` (the single source; never edit the outputs by hand).

- `running_example.sqlite`: 17 events, 6 handling units (slab s1, coils c1 to c5), 28 e2o relations.
- `inputs/*.csv`: the configuration inputs as tables (handling units, movement events, transformation events, target and pickup locations), and `inputs/locations.csv`, the location context for visits (agg, vehicles, storage units; draft).
- `derived/locations_level_{k}.csv`: the derived location mapping of each level k = 0..3, written by `notebooks/location_derivation.ipynb` (see `docs/resources/location-derivation.md`, section 7).
- `configuration.json`: the configuration below, for "Load configuration" in the form (hand-written; a test checks it matches the tests' configuration).

## Configuration that reproduces the example
- Handling units: object types `slab`, `coil` (or `inputs/handling_units.csv`, column `object`).
- Movement events: activities `crane move`, `load truck`, `unload truck` (or attribute `event_group` = `transport`, or `inputs/movement_events.csv`).
- Transformation events: activities `cast slab`, `roll`, `cut` (or attribute `event_group` = `transformation`, or `inputs/transformation_events.csv`).
- Target locations: event attribute `to_loc` (or `inputs/target_locations.csv`, columns `event`, `location`).
- Pickup locations: event attribute `from_loc` (or `inputs/pickup_locations.csv`).

Example time t is 2026-01-01 00:00 plus t hours.
E2O qualifiers: `produced`/`consumed` at the transformation events, `handled` otherwise (data only; the concept does not use them yet).
